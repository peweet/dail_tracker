# Native PDF firewall tokenizer - 2026-08-27

## Trigger

Use this when a task mentions native PDF parsing, pypdf, customer-PDF sealing,
Rust acceleration, PDF firewall parity, PDF scan workers, or a claimed report
latency reduction.

## Durable lesson

The customer-PDF firewall is a fail-closed authority boundary. A native speed
path may tokenize only one already-decoded content stream; it is not a generic
PDF document parser, renderer or replacement for the existing WeasyPrint/PDF
shell.

Keep the versioned `dail-siting-pdf-firewall-parity/1` corpus pinned to an
accepted base, derive mutations only at runtime, and require each negative case
to trigger its own specific refusal rather than a generic scan failure. The
initial 13 live cases are a minimum seed, not grammar or whole-document
coverage.

Default to pypdf. Shadow mode must return pypdf's operations while retaining
only aggregate parity counters. Direct mode needs an explicit acknowledgement
and must refuse any native absence, fault, malformed packet or unsupported
grammar without falling back. The external-release verifier must reject any
non-disabled native tokenizer mode until corpus, actual artifact-pool capacity
and issued-PDF propagation evidence are promoted.

On the four-vCPU Siting host, the independent sealing scan pool already runs at
four spawned workers. Do not add a fifth worker or a persistent pool from a
single-artifact benchmark. The local native result was a 17--23% reduction in
the serial final-byte firewall substage only; it is not an end-to-end, GPU or
Hetzner capacity claim.
